\section*{Введение}
\addcontentsline{toc}{section}{Введение}

Нейронные сети всё активнее применяются там, где ошибка недопустима:
системы управления беспилотными автомобилями, программное обеспечение авиационных
бортовых компьютеров, алгоритмы медицинской диагностики.
При этом стандартные методы тестирования принципиально не дают гарантий:
тест проверяет конкретный входной вектор, а не всё множество допустимых входов.
Формальная верификация решает именно эту задачу~--- она даёт математическое
доказательство того, что сеть ведёт себя правильно для \emph{любого} входа
из заданной области, а не только для проверенных
примеров\cite{Guidotti2019Enhancing}.

Практическое применение верификации долго ограничивалось небольшими сетями.
Современные верификаторы, прежде всего $\alpha,\beta$-CROWN~--- победитель
соревнования VNN-COMP нескольких лет подряд,~--- работают на GPU и используют
алгоритмы распространения границ (bound propagation): IBP, CROWN,
$\alpha$-CROWN. Узкое место этих алгоритмов~--- память: весовые матрицы
и матрицы линейной релаксации должны целиком помещаться на одном ускорителе.
Настоящая работа посвящена тому, как снять это ограничение за счёт методов
параллелизма, разработанных для обучения больших языковых моделей.

\subsection*{Формальная постановка задачи верификации}

Пусть нейронная сеть задаёт функцию
$f: \mathbb{R}^n \to \mathbb{R}^m$.
Задача верификации~--- проверить, выполняется ли для всех входов
из допустимого множества $\mathcal{X} \subseteq \mathbb{R}^n$ некоторое
свойство выхода $\psi$:

$$\forall \mathbf{x} \in \mathcal{X},\quad \psi(f(\mathbf{x}))$$

На практике верификаторы решают \emph{двойственную} задачу: ищут контрпример~---
вход $\mathbf{x} \in \mathcal{X}$, нарушающий $\psi$. Это задача проверки выполнимости:

$$\exists \mathbf{x} \in \mathcal{X} : \neg\psi(f(\mathbf{x}))$$

Если задача невыполнима (UNSAT)~--- свойство доказано для всей области.
Если выполнима (SAT)~--- найден контрпример\cite{marzari2025advancingneuralnetworkverification}.

\textbf{Локальная робастность.}
Наиболее распространённое верифицируемое свойство~--- устойчивость классификатора
к малым возмущениям входа. Для образца $\mathbf{x}_0$ правильного класса $c$
и нормы $L_p$ оно записывается так: при любом
$\mathbf{x}$ с $\|\mathbf{x} - \mathbf{x}_0\|_p \le \epsilon$ должно выполняться
$f(\mathbf{x})_c > f(\mathbf{x})_j$ для всех $j \neq c$\cite{DBLP:journals/corr/abs-2002-03339}.
Помимо этого, в задачах управления используются функциональные спецификации
на физических переменных~--- типичный пример~--- система ACAS~Xu\cite{Demarchi2023SupportingStandardization}.

\subsection*{Стандарт VNN-LIB}

До 2020 года каждый верификатор использовал собственный формат описания сети
и свойств, что делало прямое сравнение инструментов невозможным.
Стандарт VNN-LIB (Verification of Neural Networks Library), разработанный
сообществом, унифицировал язык спецификаций на базе SMT-LIB: входные и
выходные переменные, линейные ограничения на них, UNSAT/SAT-семантика\cite{VNNLIBWebsite}.
Совместно с форматом ONNX для хранения весов VNN-LIB образует инфраструктуру
соревнований VNN-COMP, где бенчмарки и инструменты разрабатываются независимо\cite{arXiv2212VNNCOMP2022}.

Пример спецификации~--- проверка того, что выход не превышает порог:
\begin{lstlisting}[caption={Пример VNN-LIB спецификации},label={lst:smtlib}]
(declare-const X Real)
(declare-const Y_out Real)
(assert (>= X 0.0))
(assert (<= X 1.0))
(assert (= Y_out (network_output X)))
(assert (> Y_out 5.0))   ; нарушение свойства
\end{lstlisting}

\subsection*{Вычислительная сложность}

Задача верификации NP-полна уже для однослойных ReLU-сетей: 3-SAT сводится
к ней полиномиально, поскольку нейрон ReLU может эмулировать логический
вентиль\cite{arXiv2403RobustnessVerification}.
Для сетей с гладкими активациями (Sigmoid, Tanh, GELU) сложность ещё выше~---
$\exists\mathbb{R}$-complete, то есть задача сводится к поиску решений
систем полиномиальных неравенств над вещественными числами\cite{NeurIPS2021ExistsRComplete}.
Для отдельных классов рекуррентных сетей задача достижимости алгоритмически
неразрешима в общем виде\cite{IJCAI2018ReachabilityDNN}.

На практике это означает, что \emph{полный} верификатор обязан использовать
экспоненциальный в худшем случае перебор (Branch-and-Bound), тогда как
\emph{неполный} заменяет его полиномиальной релаксацией ценой потери гарантий.
Именно этот компромисс~--- полнота против масштабируемости~--- определяет
архитектуру современных верификаторов и является отправной точкой данной работы.

\subsection*{Смежные работы}

\textbf{Параллельная верификация.}
Первые попытки масштабирования верификации использовали распределённые
CPU-кластеры.
Инструмент Marabou\cite{arXiv2401Marabou2} реализует алгоритм
Split-and-Conquer (SNC): исходный запрос рекурсивно делится на независимые
подзадачи, которые раздаются воркерам с ограничением по времени;
если воркер не укладывается, подзадача дробится дальше.
Wu~et~al.\cite{WuParallelVerification2020} исследовали стратегии разбиения~---
по входному пространству и по состояниям ReLU~--- и показали, что
распределение по тысячам облачных инстансов делает верифицируемыми задачи,
недоступные для одного CPU.
Принципиальный сдвиг произошёл с переходом на GPU: $\beta$-CROWN\cite{betaCROWN2021}
предложил батчевую обработку поддоменов~--- тысячи ветвей BaB вычисляются
за один матричный проход~--- что дало на порядки более высокую пропускную
способность по сравнению с CPU-решателями.

\textbf{Память как ограничение.}
Батчевый BaB на GPU упирается в другую стену~---
каждый поддомен хранит per-neuron $\alpha$/$\beta$-тензоры, и при глубоких
сетях совокупный объём превышает VRAM даже одного A100.
Существующие решения работают на уровне алгоритма: декомпозиция сети
на последовательные блоки (compositional verification) или отсечение
ненужных коэффициентов в CROWN-backward~--- но ни одно из них не применяет
шардирование весовых матриц по нескольким GPU.

\textbf{Параллелизм LLM за пределами обучения.}
Методы параллелизма, разработанные для обучения LLM~---
ZeRO\cite{ZeROPaper}, Tensor Parallelism\cite{MegatronLM2020}~---
уже мигрировали в область инференса: ZeRO-Inference\cite{RajbhandariZeROInference2022}
шардирует веса модели по GPU и выгружает неиспользуемые шарды в CPU-память,
позволяя запускать модели, не помещающиеся на одном ускорителе.
Формальная верификация распределённых фреймворков обучения~--- отдельная
активная линия исследований, однако она направлена на проверку корректности
самих параллельных вычислений, а не на применение параллелизма внутри
верификационного решателя.

\textbf{Вклад данной работы.}
Ни одна из известных работ не адаптирует Tensor Parallelism или FSDP
непосредственно к алгоритмам bound propagation (CROWN, $\alpha$-CROWN,
$\beta$-CROWN).
Настоящая работа заполняет этот пробел: реализованы TP-операторы для
шардирования весов и A-матриц по нескольким GPU, а также послойный FSDP
AllGather/free без изменения вычислительного графа~--- что
сохраняет побитовую идентичность bounds и совместимость с полной
верификацией через BaB.
