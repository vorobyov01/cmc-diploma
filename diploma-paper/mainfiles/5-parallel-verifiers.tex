\section{Применение Tensor Parallelism к верификации нейронных сетей}

Методы параллелизма, описанные в предыдущем разделе, были разработаны 
для обучения нейронных сетей. В данном разделе обосновывается выбор 
Tensor Parallelism для задачи верификации, анализируется его 
применимость к алгоритмам bound propagation и описываются трудности 
интеграции с полной верификацией.

\subsection{Почему Tensor Parallelism подходит для верификации}

Алгоритмы распространения границ (CROWN, $\alpha$-CROWN) сводят 
вычисление bounds к цепочке матричных умножений, выполняемых 
обратным проходом по вычислительному графу сети. Каждый линейный 
слой с весовой матрицей $W$ порождает умножение вида 
$A \leftarrow A \cdot W$ при обратном проходе, где $A$~--- матрица 
коэффициентов линейной релаксации. Эта операция структурно идентична 
backward pass в обучении, что делает TP естественным выбором:

\begin{enumerate}
    \item \textbf{Память доминируется весами.} Для полносвязных сетей 
    с большими скрытыми слоями весовые матрицы составляют основную 
    часть потребления GPU-памяти. TP разрезает эти матрицы, обеспечивая 
    линейное снижение памяти с ростом числа GPU.
    
    \item \textbf{Коммуникационный паттерн совпадает.} В CROWN backward 
    каждый слой вносит один \texttt{AllReduce}~--- точно так же, как 
    при обучении с TP. Все промежуточные вычисления выполняются 
    локально на каждом GPU.
    
    \item \textbf{Вычислительный граф не меняется.} В отличие от PP, 
    где граф разрезается на стадии, TP сохраняет единый вычислительный 
    граф на всех GPU. Это критично для \texttt{auto\_LiRPA}, которая 
    строит граф bound propagation поверх графа исходной сети.
\end{enumerate}

\subsection{Почему другие методы параллелизма менее применимы}

\textbf{Pipeline Parallelism} требует разрезания модели на 
последовательные стадии. Однако алгоритм CROWN выполняет \textit{обратный 
проход} по всем слоям: для вычисления bounds выходного слоя 
необходимы веса \textit{всех} предшествующих слоёв одновременно. 
При PP каждый GPU хранит только свою стадию, что делает невозможным 
полный обратный проход без пересылки весов между GPU~--- 
фактически сводя PP к менее эффективному варианту TP 
с point-to-point коммуникацией вместо коллективных операций.

\textbf{Data Parallelism / FSDP} оптимизирован для обучения, 
где каждый GPU обрабатывает свою часть данных (mini-batch). 
В задаче верификации нет обучающей выборки, состояний оптимизатора 
или градиентов в привычном смысле~--- есть единственная 
спецификация, которую необходимо проверить. FSDP мог бы снизить 
потребление памяти за счёт шардирования весов, но потребовал бы 
\texttt{AllGather} перед \textit{каждым} слоем в обратном проходе 
CROWN, что создаёт существенно больший коммуникационный оверхед, 
чем один \texttt{AllReduce} на пару слоёв в TP.

\subsection{Реализация TP для bound propagation в \texttt{auto\_LiRPA}}

Для интеграции TP в \texttt{auto\_LiRPA}\cite{AutoLiRPARepo} 
реализованы следующие компоненты:

\begin{enumerate}
    \item \textbf{Операторы TP:} Пользовательские операторы 
    \texttt{BoundLinearTP\_Col} и \texttt{BoundLinearTP\_Row}, 
    наследующие от \texttt{BoundLinear}. Они хранят шардированные 
    весовые матрицы и добавляют \texttt{AllReduce} в метод 
    \texttt{bound\_backward}, обеспечивая корректное распространение 
    границ через распределённые слои.
    
    \item \textbf{ONNX-интеграция:} Пользовательские операторы 
    (\texttt{customOp::TPLinearCol}, \texttt{customOp::TPLinearRow}) 
    с \texttt{torch.autograd.Function} и ONNX \texttt{symbolic}, 
    позволяющие JIT-трассировке PyTorch корректно строить 
    вычислительный граф.
    
    \item \textbf{Автоматическое шардирование:} Функция 
    \texttt{tp\_shard\_bounded\_module}, которая принимает 
    произвольный \texttt{BoundedModule} (включая загруженный 
    из ONNX) и автоматически заменяет чередующиеся пары 
    \texttt{BoundLinear} на \texttt{BoundLinearTP\_Col/Row}, 
    шардируя весовые матрицы по текущему числу GPU.
    
    \item \textbf{Зонирование шардированных подграфов:} 
    Между каждой парой Column--Row узлов формируется 
    <<шардированная зона>>~--- подграф, в котором активации 
    имеют уменьшенную размерность на каждом GPU. Узлы 
    в этих зонах (включая ReLU) обрабатываются локально, 
    без синхронизации между GPU.
\end{enumerate}

\subsection{Трудности интеграции с полной верификацией}

Полная верификация (Branch-and-Bound) с TP представляет 
значительно более сложную задачу по сравнению с неполной 
верификацией. Основные трудности:

\begin{enumerate}
    \item \textbf{Синхронизация решений о ветвлении.} 
    В Branch-and-Bound каждый шаг выбирает нейрон для фиксации 
    его состояния (активный/неактивный). При TP нейроны 
    шардированных слоёв распределены по GPU, и каждый GPU 
    <<видит>> только свою часть. Выбор нейрона для ветвления 
    требует глобальной координации: сбора статистик со всех 
    GPU и рассылки решения.
    
    \item \textbf{Параметры $\beta$.} $\beta$-CROWN кодирует 
    ограничения ветвления через двойственные переменные $\beta$. 
    Для нейронов в шардированных зонах $\beta$ определены 
    локально на каждом GPU, но их влияние распространяется 
    через \texttt{AllReduce} на глобальные bounds, что 
    требует аккуратной координации обновлений.
    
    \item \textbf{Масштабирование дерева поиска.} BaB может 
    генерировать миллионы подзадач. Параллельная обработка 
    подзадач на нескольких GPU (Batch BaB) уже реализована 
    в Alpha-Beta-CROWN для одного GPU. Распространение этого 
    подхода на TP требует, чтобы каждая подзадача 
    в батче использовала одинаковую TP-конфигурацию, что 
    усложняет балансировку нагрузки.
\end{enumerate}

В данной работе реализована и исследована неполная верификация 
с TP, которая является необходимым фундаментом для будущей 
полной интеграции.
