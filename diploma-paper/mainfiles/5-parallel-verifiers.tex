\section{Применение параллелизма к верификации нейронных сетей}

Методы параллелизма, описанные в предыдущем разделе, были разработаны 
для обучения нейронных сетей. В данном разделе обосновывается выбор 
Tensor Parallelism и FSDP для задачи верификации, анализируется их 
применимость к алгоритмам bound propagation и описываются трудности 
интеграции с полной верификацией.

\subsection{Почему Tensor Parallelism подходит для верификации}

Алгоритмы распространения границ (CROWN, $\alpha$-CROWN) сводят 
вычисление bounds к цепочке матричных умножений, выполняемых 
обратным проходом по вычислительному графу сети. Каждый линейный 
слой с весовой матрицей $W$ порождает умножение вида 
$A \leftarrow A \cdot W$ при обратном проходе, где $A$~--- матрица 
коэффициентов линейной релаксации. Эта операция структурно идентична 
backward pass в обучении, что делает TP естественным выбором:

\begin{enumerate}
    \item \textbf{Память доминируется весами.} Для полносвязных сетей 
    с большими скрытыми слоями весовые матрицы составляют основную 
    часть потребления GPU-памяти. TP разрезает эти матрицы, обеспечивая 
    линейное снижение памяти с ростом числа GPU.
    
    \item \textbf{Коммуникационный паттерн совпадает.} В CROWN backward 
    каждый слой вносит один \texttt{AllReduce}~--- точно так же, как 
    при обучении с TP. Все промежуточные вычисления выполняются 
    локально на каждом GPU.
    
    \item \textbf{Вычислительный граф не меняется.} В отличие от PP, 
    где граф разрезается на стадии, TP сохраняет единый вычислительный 
    граф на всех GPU. Это критично для \texttt{auto\_LiRPA}, которая 
    строит граф bound propagation поверх графа исходной сети.
\end{enumerate}

\subsection{Влияние Tensor Parallelism на точность bounds}
\label{sec:tp-precision-loss}

Tensor Parallelism обеспечивает близкое к линейному снижение 
памяти, однако его ключевой недостаток~--- потеря точности 
bounds, растущая с числом шардированных зон. 
Эта потеря не является ошибкой реализации: она является 
фундаментальным следствием того, как bound propagation 
взаимодействует с частичными весовыми матрицами.

\subsubsection{Обратное распространение в CROWN}

Напомним, что CROWN вычисляет линейные bounds выхода сети 
как функцию входа. Для сети с~$d$ слоями и весовыми 
матрицами $W_1, \ldots, W_d$ обратный проход CROWN строит 
A-матрицу~--- произведение линеаризованных весов:
$$A = \Lambda_d W_d \cdot \Lambda_{d-1} W_{d-1} \cdots \Lambda_1 W_1,$$
где $\Lambda_i = \mathrm{diag}(\lambda_i)$~--- диагональная матрица 
коэффициентов линейной релаксации ReLU (значения из $[0, 1]$, 
определяемые по промежуточным bounds нейронов).

Итоговые bounds принимают вид:
$$\ell \leq A \cdot \mathbf{x} + \mathbf{b} \leq u,$$
где $\mathbf{x}$~--- входной вектор в пределах 
$\varepsilon$-окрестности. Ключевое свойство: $A$~--- единая 
линейная функция от \textit{исходного} входа, сохраняющая 
зависимости между переменными на протяжении всех слоёв.

\subsubsection{Проблема CROWN в шардированных зонах}

При TP каждая пара Column--Row формирует 
<<шардированную зону>>~--- подграф, в котором активации 
имеют размерность $h/P$ на каждом GPU вместо~$h$.
Рассмотрим, что происходит при обратном проходе CROWN 
через такую зону.

Пусть слой $W_i \in \mathbb{R}^{h \times h}$ шардирован 
по столбцам: GPU~$r$ хранит $W_i^{(r)} \in \mathbb{R}^{(h/P) \times h}$. 
При CROWN backward A-матрица предыдущего слоя имеет 
полную размерность $h$:
$$A \leftarrow A \cdot \Lambda_i W_i.$$
Для этого умножения каждому GPU необходима \textit{полная} 
матрица $W_i$, однако каждый GPU хранит лишь $W_i^{(r)}$~--- 
$h/P$ строк. Выполнить корректное умножение без коммуникации 
невозможно.

Для пары Column--Row \textit{без} промежуточных слоёв (без 
ReLU между ними) эта проблема решаема: Row-слой выполняет 
\texttt{AllReduce}, восстанавливая полный результат.
Но если между Column и Row находятся ReLU-слои (как в 
типичных сетях с $> 2$ слоями), ситуация усложняется:

\begin{enumerate}
    \item Для выбора коэффициентов $\lambda_i$ (релаксации ReLU) 
    CROWN необходимо знать \textit{промежуточные bounds} 
    нейронов в шардированной зоне.
    
    \item Вычисление точных промежуточных bounds методом CROWN 
    потребовало бы отдельного обратного прохода от каждого 
    промежуточного слоя до входа~--- с коммуникацией 
    на каждом шаге. Это сводит на нет экономию памяти 
    и значительно увеличивает коммуникационные расходы.
    
    \item Альтернатива~--- использовать IBP (Interval Bound 
    Propagation) для вычисления промежуточных bounds внутри 
    шардированных зон. IBP не требует A-матриц и работает 
    послойно с локальными весами.
\end{enumerate}

\subsubsection{Почему IBP существенно менее точен}

IBP и CROWN решают одну задачу~--- вычисление bounds для 
выхода нейронной сети,~--- но принципиально различаются 
в обращении с зависимостями между переменными.

\textbf{CROWN} поддерживает глобальную линейную зависимость 
$y = A \mathbf{x} + \mathbf{b}$, где $A$ учитывает влияние 
каждого входного компонента на выход через \textit{все} 
промежуточные слои. Bounds вычисляются однократно:
$$lb = \sum_j \min(A_j x_j^L, A_j x_j^U) + b, \quad
  ub = \sum_j \max(A_j x_j^L, A_j x_j^U) + b.$$

\textbf{IBP} вычисляет bounds послойно. Для $i$-го слоя 
с весами $W_i$ и входным интервалом $[\ell_{i-1}, u_{i-1}]$:
\begin{align*}
\ell_i &= W_i^+ \ell_{i-1} + W_i^- u_{i-1} + b_i, \\
u_i &= W_i^+ u_{i-1} + W_i^- \ell_{i-1} + b_i,
\end{align*}
где $W_i^+ = \max(W_i, 0)$, $W_i^- = \min(W_i, 0)$.

Критическое отличие: IBP теряет информацию о корреляции 
между компонентами промежуточного вектора. На каждом слое 
IBP рассматривает каждый элемент интервала как независимую 
переменную. Это приводит к \textit{эффекту обёртки} 
(wrapping effect)\cite{moore2009interval}~--- артефакту 
интервальной арифметики, при котором ширина bounds 
может расти экспоненциально с числом слоёв.

\textbf{Пример.} Рассмотрим двумерный вход $\mathbf{x} = (x_1, x_2)^T$ 
с $x_1, x_2 \in [-1, 1]$ и матрицу
$W = \begin{pmatrix} 1 & 1 \\ 1 & -1 \end{pmatrix}$.

CROWN: $y = W\mathbf{x}$, откуда $y_1 = x_1 + x_2 \in [-2, 2]$, 
$y_2 = x_1 - x_2 \in [-2, 2]$. Повторное применение $W$:
$z_1 = y_1 + y_2 = 2x_1 \in [-2, 2]$.

IBP: первый слой даёт $y_1 \in [-2, 2]$, $y_2 \in [-2, 2]$~--- 
совпадает. Но при повторном применении $W$ IBP считает $y_1$ и $y_2$ 
\textit{независимыми}: $z_1 = y_1 + y_2 \in [-4, 4]$~--- 
в два раза шире истинного. CROWN, отслеживая зависимость 
$y_1 = x_1 + x_2$, $y_2 = x_1 - x_2$, даёт точный результат.

\subsubsection{Количественный эффект: рост ошибки с глубиной}

Для случайной весовой матрицы с элементами порядка $O(1/\sqrt{h})$ 
(типичная инициализация) ширина IBP-интервала после $k$ слоёв 
растёт как $O(\rho^k)$, где $\rho$~--- спектральный радиус 
обобщённой матрицы абсолютных значений $|W|$. При $h = 256$ 
и стандартной инициализации $\rho \approx 1$, но даже 
при $\rho$ лишь незначительно больше единицы накопление 
ошибки за $k$ слоёв приводит к существенному расширению bounds.

Экспериментальные данные (Таблица~\ref{tab:tp-correctness}) 
подтверждают эту зависимость:

\begin{itemize}
    \item \textbf{1 пара Col-Row} (модель 256$\times$2): 
    шардированная зона содержит 0~промежуточных ReLU-слоёв.
    IBP fallback не используется; CROWN backward проходит 
    через зону целиком. Отклонение $\sim 10^{-8}$ 
    (машинный эпсилон \texttt{float32}).
    
    \item \textbf{2 пары Col-Row} (модель 256$\times$4): 
    каждая зона содержит промежуточный ReLU. IBP используется 
    для промежуточных bounds внутри зон. Отклонение $\sim 2.5$~--- 
    рост на 8 порядков.
    
    \item \textbf{3 пары Col-Row} (модель 256$\times$6): 
    три зоны, каждая с промежуточным ReLU. Отклонение 
    $\sim 750$~--- ещё на 2 порядка больше.
\end{itemize}

Таким образом, потеря точности при TP обусловлена не 
арифметическими ошибками распределённых вычислений, 
а \textit{заменой метода}: внутри шардированных зон 
точный метод CROWN вынужденно заменяется на грубый IBP.
С каждой дополнительной шардированной зоной добавляется 
<<слой>> IBP-аппроксимации, ошибка которого накапливается 
мультипликативно по глубине сети.

\textbf{Следствие для практики:} TP-верификация эффективна 
для моделей с малой глубиной (1--2 пары шардированных слоёв), 
где IBP fallback минимален. Для глубоких моделей 
($\geq 4$ шардированных зон) потеря точности может 
сделать bounds практически бесполезными для верификации. 
Это мотивирует разработку FSDP-подхода 
(раздел~\ref{sec:fsdp-memory-theory}), свободного 
от данного ограничения.

\subsection{Сравнение методов параллелизма для верификации}

\textbf{Pipeline Parallelism} требует разрезания модели на 
последовательные стадии. Однако алгоритм CROWN выполняет \textit{обратный 
проход} по всем слоям: для вычисления bounds выходного слоя 
необходимы веса \textit{всех} предшествующих слоёв одновременно. 
При PP каждый GPU хранит только свою стадию, что делает невозможным 
полный обратный проход без пересылки весов между GPU~--- 
фактически сводя PP к менее эффективному варианту TP 
с point-to-point коммуникацией вместо коллективных операций.

\textbf{FSDP (Fully Sharded Data Parallelism)} шардирует веса модели 
по GPU, собирая их \texttt{AllGather}-операцией непосредственно 
перед использованием каждого слоя. В контексте верификации FSDP 
обладает принципиальным преимуществом перед TP: вычисления 
математически \textit{идентичны} однопроцессорному режиму, 
поскольку каждый слой работает с полной весовой матрицей (временно 
собранной из шардов). Это означает отсутствие потерь точности 
bounds~--- в отличие от TP, где промежуточные bounds в шардированных 
зонах вынуждены использовать менее точный метод IBP. Ценой 
является больший коммуникационный оверхед: \texttt{AllGather} 
перед каждым слоем вместо одного \texttt{AllReduce} на пару 
слоёв в~TP. Однако при использовании быстрых NVLink-соединений 
этот оверхед не является узким местом для типичных моделей.

Сравнение двух методов в контексте верификации:
\begin{itemize}
    \item \textbf{TP}: шардирует и веса, и A-матрицы, 
    давая до $\sim\!2\times$ снижение пиковой памяти. 
    Но точность bounds падает с ростом числа шардированных зон 
    (IBP fallback), что ограничивает глубину верифицируемых моделей.
    
    \item \textbf{FSDP}: шардирует \textit{только веса}, 
    A-матрицы остаются полноразмерными. Пиковая память 
    снижается на 25--39\%, но baseline-память (хранение весов) 
    уменьшается на 80--90\%. При этом bounds \textit{побитово 
    идентичны} однопроцессорному режиму, что критично 
    для полной верификации ($\beta$-CROWN).
\end{itemize}

\subsection{Реализация TP для bound propagation в \texttt{auto\_LiRPA}}

Для интеграции TP в \texttt{auto\_LiRPA}\cite{AutoLiRPARepo} 
реализованы следующие компоненты:

\begin{enumerate}
    \item \textbf{Операторы TP:} Пользовательские операторы 
    \texttt{BoundLinearTP\_Col} и \texttt{BoundLinearTP\_Row}, 
    наследующие от \texttt{BoundLinear}. Они хранят шардированные 
    весовые матрицы и добавляют \texttt{AllReduce} в метод 
    \texttt{bound\_backward}, обеспечивая корректное распространение 
    границ через распределённые слои.
    
    \item \textbf{ONNX-интеграция:} Пользовательские операторы 
    (\texttt{customOp::TPLinearCol}, \texttt{customOp::TPLinearRow}) 
    с \texttt{torch.autograd.Function} и ONNX \texttt{symbolic}, 
    позволяющие JIT-трассировке PyTorch корректно строить 
    вычислительный граф.
    
    \item \textbf{Автоматическое шардирование:} Функция 
    \texttt{tp\_shard\_bounded\_module}, которая принимает 
    произвольный \texttt{BoundedModule} (включая загруженный 
    из ONNX) и автоматически заменяет чередующиеся пары 
    \texttt{BoundLinear} на \texttt{BoundLinearTP\_Col/Row}, 
    шардируя весовые матрицы по текущему числу GPU.
    
    \item \textbf{Зонирование шардированных подграфов:} 
    Между каждой парой Column--Row узлов формируется 
    <<шардированная зона>>~--- подграф, в котором активации 
    имеют уменьшенную размерность на каждом GPU. Узлы 
    в этих зонах (включая ReLU) обрабатываются локально, 
    без синхронизации между GPU.
\end{enumerate}

\subsection{Реализация FSDP для bound propagation в \texttt{auto\_LiRPA}}

В дополнение к Tensor Parallelism, в данной работе реализован 
альтернативный подход~--- FSDP для верификации, не требующий 
специализированных операторов и обеспечивающий идеальную точность 
bounds.

\subsubsection{Архитектура решения}

Реализация FSDP состоит из трёх компонентов:

\begin{enumerate}
    \item \textbf{Шардирование весов.} Функция 
    \texttt{fsdp\_shard\_bounded\_module} обходит граф 
    \texttt{BoundedModule}, находит все узлы \texttt{BoundParams}, 
    соответствующие весовым матрицам линейных слоёв, 
    и заменяет каждую матрицу $W \in \mathbb{R}^{k \times n}$ 
    на шард $W^{(r)} \in \mathbb{R}^{(k/P) \times n}$, 
    где $P$~--- число GPU, $r$~--- ранг текущего процесса.
    
    \item \textbf{Прозрачный AllGather.} Метод \texttt{forward()} 
    класса \texttt{BoundParams} расширен: при обнаружении флага 
    шардирования выполняется \texttt{dist.all\_gather}, 
    собирающий полную весовую матрицу из шардов всех GPU. 
    Полная матрица возвращается как результат forward и 
    используется всеми нижестоящими операциями (IBP, CROWN) 
    без модификации.
    
    \item \textbf{Послойное освобождение памяти.} Хуки 
    \texttt{fsdp\_gather\_node}/\texttt{fsdp\_free\_node} 
    интегрированы в \texttt{backward\_general} (CROWN backward) 
    и \texttt{IBP\_general} (IBP forward): полная весовая матрица 
    собирается непосредственно перед обработкой 
    \texttt{BoundLinear} и освобождается сразу после. В каждый 
    момент времени в GPU-памяти находится не более одной 
    полной весовой матрицы (помимо шардов).
\end{enumerate}

Ключевое отличие от TP: не создаются новые типы операторов, 
не изменяется вычислительный граф, не вводятся шардированные 
зоны. Общий объём реализации~--- около 100~строк кода 
(против $\sim$500 для TP).

\subsubsection{Теоретический анализ расхода памяти}
\label{sec:fsdp-memory-theory}

Пусть модель содержит $d$ линейных слоёв с весовыми матрицами 
$W_i \in \mathbb{R}^{h \times h}$ ($i = 1, \ldots, d$), 
и верификация выполняется методом CROWN для одного входного 
примера. Обозначим $P$~--- число GPU, $h$~--- размерность 
скрытого слоя.

\textbf{Память весов.} В single-GPU режиме все веса хранятся 
целиком: $M_W = d \cdot h^2$. При FSDP каждый GPU хранит 
$1/P$ каждого веса (шард), плюс \textit{одну} полную матрицу, 
временно собранную для текущего слоя:
$$M_W^{\text{FSDP}} = \frac{d \cdot h^2}{P} + h^2.$$

\textbf{Память A-матриц.} В CROWN backward для промежуточного 
слоя $i$ хранится A-матрица размера $O(h \times h)$ 
(матрица коэффициентов линейной релаксации, обратно 
распространяемая по графу). При TP A-матрицы проходят 
через шардированные слои и имеют уменьшенную размерность $h/P$, 
что сокращает их объём. При FSDP A-матрицы всегда 
имеют полную размерность $h$:
$$M_A^{\text{TP}} \propto \frac{h^2}{P}, \qquad 
  M_A^{\text{FSDP}} \propto h^2.$$

\textbf{Суммарная пиковая память.} Для TP:
$$M_{\text{peak}}^{\text{TP}} \approx 
    \frac{d \cdot h^2}{P} + \frac{C \cdot h^2}{P} 
    \approx \frac{(d + C) \cdot h^2}{P},$$
что даёт линейное снижение в $P$ раз. Для FSDP:
$$M_{\text{peak}}^{\text{FSDP}} \approx 
    \frac{d \cdot h^2}{P} + h^2 + C \cdot h^2 
    = h^2 \!\left(\frac{d}{P} + 1 + C\right),$$
где $C$~--- число одновременно хранящихся A-матриц 
(зависит от числа промежуточных слоёв).

Таким образом, FSDP экономит память \textit{только} 
на весах (первое слагаемое), тогда как TP сокращает оба слагаемых. 
Отношение пиковой памяти FSDP к single-GPU:
$$\frac{M_{\text{peak}}^{\text{FSDP}}}{M_{\text{peak}}^{\text{single}}} 
    = \frac{d/P + 1 + C}{d + C}.$$
При $d = 4$, $C \approx d = 4$, $P = 2$: коэффициент 
$\approx (2 + 1 + 4)/(4 + 4) = 7/8 = 0.875$, что соответствует 
экспериментально наблюдаемой экономии $\sim$25--34\%.

\textbf{Baseline-память} (хранение весов без A-матриц) сокращается 
существенно сильнее:
$$\frac{M_W^{\text{FSDP}}}{M_W^{\text{single}}} 
    = \frac{d/P + 1}{d} = \frac{1}{P} + \frac{1}{d},$$
что при $d = 4$, $P = 2$ даёт $0.75$, а при $d = 8$, $P = 2$ 
даёт $0.625$~--- экспериментально наблюдаемые $\sim$82--90\%.

\subsection{Трудности интеграции с полной верификацией}

Полная верификация (Branch-and-Bound) с TP представляет 
значительно более сложную задачу по сравнению с неполной 
верификацией. Основные трудности:

\begin{enumerate}
    \item \textbf{Синхронизация решений о ветвлении.} 
    В Branch-and-Bound каждый шаг выбирает нейрон для фиксации 
    его состояния (активный/неактивный). При TP нейроны 
    шардированных слоёв распределены по GPU, и каждый GPU 
    <<видит>> только свою часть. Выбор нейрона для ветвления 
    требует глобальной координации: сбора статистик со всех 
    GPU и рассылки решения.
    
    \item \textbf{Параметры $\beta$.} $\beta$-CROWN кодирует 
    ограничения ветвления через двойственные переменные $\beta$. 
    Для нейронов в шардированных зонах $\beta$ определены 
    локально на каждом GPU, но их влияние распространяется 
    через \texttt{AllReduce} на глобальные bounds, что 
    требует аккуратной координации обновлений.
    
    \item \textbf{Масштабирование дерева поиска.} BaB может 
    генерировать миллионы подзадач. Параллельная обработка 
    подзадач на нескольких GPU (Batch BaB) уже реализована 
    в Alpha-Beta-CROWN для одного GPU. Распространение этого 
    подхода на TP требует, чтобы каждая подзадача 
    в батче использовала одинаковую TP-конфигурацию, что 
    усложняет балансировку нагрузки.
\end{enumerate}

В данной работе реализованы и исследованы два подхода к неполной 
верификации: TP (максимальная экономия памяти, но с потерей 
точности bounds) и FSDP (умеренная экономия пиковой памяти, 
но с идеальной точностью bounds). FSDP, в отличие от TP, 
не изменяет вычислительный граф и потенциально совместим 
с полной верификацией ($\beta$-CROWN), что делает его 
перспективным направлением для будущей интеграции.
