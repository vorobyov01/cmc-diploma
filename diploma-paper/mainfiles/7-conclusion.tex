\section{Заключение}

\subsection{Результаты работы}

Работа посвящена адаптации методов параллелизма из обучения
больших языковых моделей для задачи формальной верификации нейронных
сетей. Реализованы и экспериментально проверены два подхода:
Tensor Parallelism (TP) и Fully Sharded Data Parallelism (FSDP),
последний охватывает в том числе полную верификацию через
$\beta$-CROWN и Branch-and-Bound.

Получены следующие результаты:

\begin{enumerate}
    \item \textbf{Линейное снижение памяти с TP.}
    TP снижает пиковое потребление GPU-памяти пропорционально
    числу GPU (коэффициент $\approx 1.985$ при $P = 2$),
    разбивая как матрицы весов, так и A-матрицы CROWN.
    Были реализованы специализированные операторы
    \texttt{BoundLinearTP\_Col}/\texttt{Row} с корректным
    \texttt{AllReduce} и разбиением вычислительного графа.
    Bounds удовлетворяют soundness для всех протестированных моделей,
    но для сетей с несколькими шардированными зонами
    наблюдается потеря точности из-за вынужденного
    использования IBP для промежуточных bounds.

    \item \textbf{Идеальная точность bounds с FSDP.}
    FSDP разбивает матрицы весов, собирая их через \texttt{AllGather} послойно.
    Все протестированные конфигурации (MLP различной
    ширины и глубины, ONNX-модели из VNN-COMP) дали
    bounds, \textit{побитово идентичные} однопроцессорному
    режиму ($\Delta lb = \Delta ub = 0.00$). Baseline-память
    (хранение весов) сокращается на 80--90\%; пиковая
    память при \texttt{compute\_bounds}~--- на 34--39\%
    (на широких MLP с доминирующими весами).

    \item \textbf{Автоматическое шардирование.}
    Для обоих подходов реализованы функции автоматического
    шардирования (\texttt{tp\_shard\_bounded\_module},
    \texttt{fsdp\_shard\_bounded\_module}), преобразующие
    произвольный \texttt{BoundedModule} (включая загруженный
    из ONNX) без ручного переписывания модели.

    \item \textbf{FSDP в полной верификации ($\beta$-CROWN+BaB).}
    Честное сравнение (одинаковый batch, число раундов,
    флаг \texttt{force\_synchronous}) показало: FSDP
    добавляет $\le\!5$~МБ overhead AllGather и не изменяет
    workload. На малых моделях ($\sim\!1.5$~МБ весов)
    экономии нет~--- узкое место здесь alpha-тензоры
    ($\gg 1$~ГБ), а не веса. FSDP не вредит точности
    и масштабируется на произвольные BaB-задачи.

    \item \textbf{FSDP для свёрточных слоёв (\texttt{BoundConv}).}
    Шардирование адаптировано и для \texttt{BoundConv}
    (по оси out\_channels). Валидация на CIFAR-100 ResNet
    medium/large (VNN-COMP'24) показала побитово идентичные bounds,
    корректность была подтверждена. На ResNet-large ($\sim\!95$~МБ
    весов, $>4$~ГБ $\alpha$-тензоров) экономия памяти
    от разбиения весов перекрывается от overhead на буферы для AllGather,
    что подтверждает доминирование $\alpha$-тензоров.

    \item \textbf{JIT-совместимость и запуск ViT.}
    Для верификации трансформеров потребовалось устранить
    несовместимости JIT-компиляции в \texttt{BoundReshape},
    \texttt{BoundConcat} и \texttt{BoundConstantOfShape}.
    После исправлений модель \texttt{pgd\_2\_3\_16}
    из VNN-COMP'23 корректно запускается
    в $\alpha,\beta$-CROWN с FSDP, давая идентичные эталону bounds.
\end{enumerate}

В завершении можно сказать, что TP и FSDP представляют
два полюса компромисса \textit{память~--- точность}:
TP обеспечивает максимальную экономию памяти ($\sim\!2\times$),
но теряет точность bounds с увеличением глубины модели;
FSDP даёт меньшую экономию пиковой памяти (34--39\%
при incomplete-верификации), но сохраняет побитовую
точность и совместим с $\beta$-CROWN+BaB.

\subsection{Дальнейшая работа}

\textbf{Разбиение $\alpha$-тензоров.}
Эксперименты~6--8 показали, что в $\alpha$-CROWN+BaB
узкое место по памяти это per-neuron $\alpha$-тензоры,
а не матрицы весов. Разбиение $\alpha$-тензоров по GPU
(аналогично Domain Parallelism) позволит устранить этот
барьер и обеспечит полноценную экономию памяти
при полной верификации крупных свёрточных сетей.

\textbf{Оптимизация $\alpha$-CROWN с TP и FSDP.}
Градиентная оптимизация наклонов $\alpha$ совместима
с обоими подходами, поскольку использует тот же
backward-pass, что и CROWN.

\textbf{Масштабирование на большее число GPU.}
Эксперименты проводились при $P = 2$. Валидация на большем число GPU 
(при $P = 4, 8$) позволит практически оценить накладные 
расходы на коммуникации и определить пределы масштабируемости.
FSDP при $P = 4$ теоретически даёт $\sim\!93\%$ экономию
baseline-памяти.

\textbf{Domain-Parallel BaB с input-split branching.}
Текущая интеграция FSDP с BaB работает в синхронном режиме (все GPU обрабатывают одно поддерево).
Input-split это параллельное ветвление по разным поддоменам, позволяющее использовать несколько GPU
для ускорения BaB. Это позволит не только экономить память, но и ускорить верификацию.
