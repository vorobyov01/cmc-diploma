\section{Параллелизм в обучении нейронных сетей}

Современные нейронные сети достигают миллиардов параметров, что делает 
невозможным их обучение и даже инференс на одном ускорителе. В этом 
разделе рассматриваются основные стратегии распределения вычислений, 
разработанные для обучения больших языковых моделей 
(Large Language Models, LLM), которые впоследствии адаптируются 
в данной работе для задачи верификации.

\subsection{Масштаб современных моделей и архитектура Transformer}

Основой современных LLM является архитектура Transformer\cite{Vaswani2017Attention}, 
построенная на механизме самовнимания (self-attention). Каждый слой 
Transformer состоит из двух основных блоков:

\begin{enumerate}
    \item \textbf{Multi-Head Attention (MHA):} Вычисляет матрицы запросов, 
    ключей и значений $Q = XW_Q$, $K = XW_K$, $V = XW_V$, где 
    $W_Q, W_K, W_V \in \mathbb{R}^{d \times d}$, затем находит 
    взвешенную сумму:
    $$\mathrm{Attention}(Q, K, V) = \mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d}}\right)V.$$
    
    \item \textbf{Feed-Forward Network (FFN):} Двухслойная полносвязная сеть 
    с расширением:
    $$\mathrm{FFN}(x) = W_2 \cdot \mathrm{GELU}(W_1 x + b_1) + b_2,$$
    где $W_1 \in \mathbb{R}^{4d \times d}$ и $W_2 \in \mathbb{R}^{d \times 4d}$.
\end{enumerate}

Каждый блок содержит несколько матричных умножений с весовыми матрицами 
размера $d \times d$ или $d \times 4d$. При $d = 12288$ (GPT-3, 175 
миллиардов параметров\cite{GPT3Brown2020}) одна матрица $W_1$ 
занимает $12288 \times 49152 \times 4 \approx 2.3$~ГБ в формате float32. 
Модель из 96 таких слоёв не помещается в память одного GPU 
(типично 40--80~ГБ). Это мотивирует разработку стратегий параллелизма, 
распределяющих параметры и вычисления по нескольким ускорителям.

\subsection{Tensor Parallelism (TP)}

Tensor Parallelism, предложенный в работе Megatron-LM\cite{MegatronLM2020}, 
разделяет отдельные операции (матричные умножения) \textit{внутри слоя} 
по нескольким GPU. Ключевая идея~--- разрезать весовую матрицу 
так, чтобы каждый GPU выполнял свою часть умножения, а результаты 
синхронизировались коллективными операциями.

\subsubsection{Column Parallel Linear}

Весовая матрица $W \in \mathbb{R}^{k \times n}$ разрезается по 
столбцам (выходному измерению) на $P$ частей:
$$W = [W^{(0)} \mid W^{(1)} \mid \ldots \mid W^{(P-1)}], \quad 
  W^{(r)} \in \mathbb{R}^{k \times (n/P)}.$$
Каждый GPU $r$ хранит только свой шард $W^{(r)}$ и вычисляет локальную 
часть выхода $\mathbf{y}^{(r)} = W^{(r)\top} \mathbf{x}$. Входной 
вектор $\mathbf{x}$ реплицирован на всех GPU. После умножения каждый 
GPU содержит свою часть выхода размера $n/P$~--- активации 
\textit{шардированы} по выходному измерению.

\subsubsection{Row Parallel Linear}

Весовая матрица $W \in \mathbb{R}^{n \times m}$ разрезается по 
строкам (входному измерению):
$$W = \begin{bmatrix} W^{(0)} \\ W^{(1)} \\ \vdots \\ W^{(P-1)} \end{bmatrix}, 
  \quad W^{(r)} \in \mathbb{R}^{(n/P) \times m}.$$
Каждый GPU $r$ умножает свою часть шардированного входа 
$\mathbf{x}^{(r)}$ на свой шард веса: 
$\mathbf{z}^{(r)} = W^{(r)} \mathbf{x}^{(r)}$, 
получая \textit{частичный} результат. Полный выход собирается операцией 
\texttt{AllReduce} (суммирование частичных результатов по всем GPU):
$$\mathbf{y} = \sum_{r=0}^{P-1} \mathbf{z}^{(r)}.$$

\subsubsection{Коммуникационные операции}

Пара Column--Row Parallel образует базовый блок TP. В прямом проходе 
(forward pass) требуется один \texttt{AllReduce} после Row Parallel 
слоя. В обратном проходе (backward pass) требуется один 
\texttt{AllReduce} для градиентов перед Column Parallel слоем. 
Таким образом, каждый блок FFN добавляет два коллективных вызова. 
При использовании быстрых межGPU-связей (NVLink, NVSwitch) накладные 
расходы на коммуникацию составляют единицы процентов от общего 
времени вычислений\cite{MegatronLM2020}.

TP масштабируется в пределах одного узла (обычно до 8~GPU), так как 
\texttt{AllReduce} чувствителен к пропускной способности 
межузловых соединений.

\subsection{Pipeline Parallelism (PP)}

Pipeline Parallelism\cite{GPipePaper} разделяет модель \textit{по слоям}: 
каждый GPU хранит группу последовательных слоёв (стадию, stage). 
Вход проходит через стадии последовательно, что создаёт проблему 
<<пузыря>> (bubble): пока первый GPU обрабатывает новый микробатч, 
последний GPU простаивает.

Для уменьшения пузыря входной батч разбивается на $M$ микробатчей 
(micro-batches), которые поступают в конвейер один за другим. 
Доля простоя (bubble ratio) составляет:
$$r_{\text{bubble}} = \frac{P - 1}{M + P - 1},$$
где $P$~--- число стадий. При $M \gg P$ доля пузыря стремится к нулю, 
но при этом растёт потребление памяти для хранения промежуточных 
активаций всех микробатчей.

Достоинство PP~--- минимальная коммуникация: между стадиями передаются 
только активации одного слоя (point-to-point send/recv), а не 
результаты \texttt{AllReduce}. Это позволяет масштабировать PP 
на межузловые соединения.

\subsection{Fully Sharded Data Parallelism (FSDP)}

Data Parallelism (DP) реплицирует всю модель на каждом GPU, 
разделяя данные обучения. После прямого и обратного прохода 
градиенты усредняются операцией \texttt{AllReduce}. Основной 
недостаток~--- каждый GPU хранит полную копию модели, 
оптимизатора и градиентов.

Fully Sharded Data Parallelism (FSDP), основанный на идеях 
ZeRO\cite{ZeROPaper}, устраняет избыточность, шардируя параметры 
модели, градиенты и состояния оптимизатора по GPU. Каждый GPU 
хранит только $1/P$ часть каждого тензора. Перед вычислением 
конкретного слоя выполняется операция \texttt{AllGather}, 
собирающая полные веса со всех GPU; после обратного прохода 
через слой \texttt{ReduceScatter} распределяет усреднённые 
градиенты обратно по шардам.

FSDP обеспечивает линейное снижение потребления памяти 
с ростом числа GPU, но вводит значительный коммуникационный 
оверхед: каждый слой требует \texttt{AllGather} в forward 
и \texttt{ReduceScatter} в backward. Метод оптимизирован 
для обучения, где доминирует стоимость состояний оптимизатора 
(Adam хранит первый и второй моменты для каждого параметра, 
что утраивает объём памяти по сравнению с весами модели).
