\section{Дизайн и постановка экспериментов}

Для валидации предложенного подхода к параллельной верификации с использованием 
Tensor Parallelism был поставлен эксперимент, сравнивающий потребление GPU-памяти 
при верификации методом CROWN на одном GPU и при распределении вычислений 
на два GPU с помощью TP.

\subsection{Аппаратная конфигурация}

Эксперименты проводились на сервере со следующей конфигурацией:
\begin{itemize}
    \item 2$\times$ NVIDIA A40 (48~ГБ VRAM каждый, Ampere);
    \item межGPU-связь через NVLink;
    \item бэкенд коллективных операций: NCCL;
    \item фреймворк: PyTorch 2.x, запуск через \texttt{torchrun --nproc\_per\_node=2}.
\end{itemize}

\subsection{Архитектура модели}

В качестве объекта верификации использовалась полносвязная сеть с одним скрытым слоем:
$$f(\mathbf{x}) = W_2 \cdot \mathrm{ReLU}(W_1 \mathbf{x} + \mathbf{b}_1) + \mathbf{b}_2,$$
где $W_1 \in \mathbb{R}^{H \times D}$, $W_2 \in \mathbb{R}^{1 \times H}$, 
$D = 4096$ --- размерность входа, $H = 262144$ --- размерность скрытого слоя.

Выбор архитектуры обусловлен двумя факторами.
Во-первых, матрица $W_1$ размера $262144 \times 4096$ (около 4~ГБ в float32) 
доминирует в потреблении памяти как при прямом проходе, так и при вычислении 
backward bounds в CROWN.
Во-вторых, единственный ReLU-слой достаточен для порождения нетривиальной задачи 
верификации: CROWN требует вычисления промежуточных границ (intermediate bounds) 
для входа активации, что является основной вычислительной нагрузкой.

\subsection{Реализация Tensor Parallelism}

Для TP-варианта модель была разбита по схеме Megatron-LM\cite{MegatronLM2020}:
\begin{itemize}
    \item \textbf{Column Parallel} ($W_1$): весовая матрица разрезана по столбцам 
    (по выходному измерению). Каждый GPU хранит шард 
    $W_1^{(r)} \in \mathbb{R}^{(H/P) \times D}$, где $P$ --- число GPU.
    Выход первого слоя шардирован: каждый GPU содержит свою часть скрытого 
    представления.
    \item \textbf{Row Parallel} ($W_2$): весовая матрица разрезана по строкам 
    (по входному измерению). Каждый GPU хранит шард 
    $W_2^{(r)} \in \mathbb{R}^{1 \times (H/P)}$, вычисляет частичный результат, 
    после чего выполняется \texttt{AllReduce} (суммирование) для получения 
    полного выхода.
\end{itemize}

Для интеграции с \texttt{auto\_LiRPA}\cite{AutoLiRPARepo} были реализованы:
\begin{enumerate}
    \item Пользовательские ONNX-операторы (\texttt{customOp::TPLinearCol}, 
    \texttt{customOp::TPLinearRow}) с \texttt{torch.autograd.Function} 
    и ONNX \texttt{symbolic}, позволяющие JIT-трассировке корректно 
    строить вычислительный граф.
    \item Операторы bound propagation (\texttt{BoundLinearTP\_Col}, 
    \texttt{BoundLinearTP\_Row}), наследующие от \texttt{BoundLinear} и 
    добавляющие \texttt{AllReduce} на этапе обратного распространения границ.
\end{enumerate}

\subsection{Методология эксперимента}

Верификация выполнялась методом CROWN для свойства локальной робастности 
в $L_\infty$-норме с $\varepsilon = 0.01$ на батче из $N = 2048$ входных 
примеров размерности $D = 4096$, сгенерированных случайно.
Измерялось пиковое потребление GPU-памяти (\texttt{torch.cuda.max\_memory\_allocated}).

Сравнивались два режима:
\begin{enumerate}
    \item \textbf{Single GPU}: стандартная модель (\texttt{nn.Linear}) 
    на одном GPU, стандартный \texttt{BoundLinear} в \texttt{auto\_LiRPA}.
    \item \textbf{TP = 2}: TP-модель на двух GPU, 
    \texttt{BoundLinearTP\_Col/Row} с \texttt{AllReduce}.
\end{enumerate}

\subsection{Анализ результатов}

Результаты подтверждают основную гипотезу работы: 
Tensor Parallelism позволяет сократить пиковое потребление GPU-памяти 
при верификации нейронных сетей пропорционально числу используемых GPU.

Коэффициент снижения памяти составил:
$$k = \frac{26\,826}{13\,513} \approx 1.985,$$
что близко к теоретическому пределу $P = 2$ для двух GPU.
Незначительное отклонение от идеального значения объясняется 
нешардируемыми структурами данных: входной тензор $\mathbf{x}$ размера 
$(N \times D)$, буферы NCCL для коллективных операций, 
а также метаданные вычислительного графа \texttt{auto\_LiRPA}, 
реплицированные на каждом GPU.

Практическое следствие: модели, не помещающиеся в память одного GPU 
при верификации, могут быть верифицированы путём распределения на 
несколько GPU с линейным масштабированием доступной памяти.
