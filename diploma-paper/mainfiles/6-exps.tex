\section{Эксперименты}

\subsection{Методология и план экспериментов}

Для валидации реализованных методов~--- Tensor Parallelism (TP)
и Fully Sharded Data Parallelism (FSDP)~--- поставлены восемь
экспериментов, сгруппированных по исследуемому методу и свойству.

\textbf{Эксперименты с Tensor Parallelism (Эксп.~1--3):}
\begin{enumerate}
    \item \textbf{Потребление GPU-памяти} (OOM-тест). Цель~---
    продемонстрировать, что TP позволяет верифицировать модели,
    не помещающиеся в память одного GPU. Сравнивается пиковое
    потребление при CROWN-верификации на одном и двух GPU.

    \item \textbf{Корректность и звуковость bounds}. Цель~---
    убедиться, что TP-реализация вычисляет \textit{звуковые}
    (sound) bounds: $lb_{\text{tp}} \le lb_{\text{ref}}$ и
    $ub_{\text{tp}} \ge ub_{\text{ref}}$ для любой модели.
    Анализируется зависимость потери точности от числа
    шардированных зон.

    \item \textbf{Автоматическое шардирование на VNN-COMP}.
    Цель~--- проверить \texttt{tp\_shard\_bounded\_module}
    на ONNX-моделях MNIST-FC из VNN-COMP~2022\cite{arXiv2212VNNCOMP2022},
    подтвердив применимость за пределами вручную написанных
    PyTorch-моделей.
\end{enumerate}

\textbf{Эксперименты с FSDP (Эксп.~4--8):}
\begin{enumerate}
    \setcounter{enumi}{3}
    \item \textbf{Корректность FSDP bounds}. Цель~--- проверить,
    что FSDP даёт bounds, побитово идентичные single-GPU, для
    IBP и CROWN на моделях различной ширины и глубины.

    \item \textbf{Потребление GPU-памяти при FSDP}. Цель~---
    измерить baseline-память (хранение весов) и пиковую память
    при \texttt{compute\_bounds} в зависимости от ширины и
    глубины модели; сравнить с теоретическим прогнозом.

    \item \textbf{FSDP в полной верификации (BaB)}. Цель~---
    честно сравнить FSDP$=$2 и single-GPU в $\beta$-CROWN+BaB
    при \textit{идентичном} workload (одинаковые batch, число
    раундов, набор доменов); выявить истинное узкое место памяти.

    \item \textbf{FSDP с Vision Transformer (VNN-COMP'23)}.
    Цель~--- верифицировать запуск FSDP на трансформерной
    архитектуре (\texttt{pgd\_2\_3\_16}) после устранения
    JIT-несовместимостей; сравнить peak-память с single-GPU.

    \item \textbf{Расширение FSDP на BoundConv: CIFAR-100
    ResNet}. Цель~--- проверить корректность BoundConv-шардирования
    на свёрточных моделях VNN-COMP'24 (ResNet medium/large)
    и выяснить, является ли шардирование весов достаточным
    для экономии памяти в $\alpha$-CROWN+BaB.
\end{enumerate}

\textbf{Аппаратная конфигурация.}
Эксперименты~1--7 проводились на двух серверах с различной
топологией:
\begin{itemize}
    \item \textbf{Сервер A} (Эксп.~1--5): 2$\times$ NVIDIA A40
    (48~ГБ VRAM, архитектура Ampere), межGPU-связь через NVLink.
    \item \textbf{Сервер B} (Эксп.~6--8): 2$\times$ NVIDIA A40
    (48~ГБ VRAM), межGPU-связь через PCIe (без NVLink);
    использовался флаг \texttt{NCCL\_P2P\_DISABLE=1} для
    предотвращения зависания NCCL AllGather.
\end{itemize}
Во всех экспериментах: бэкенд коллективных операций~--- NCCL;
фреймворк~--- PyTorch 2.x; запуск через
\texttt{torchrun --nproc\_per\_node=2}.

\subsection{Эксперимент 1: потребление GPU-памяти}

\subsubsection{Архитектура модели}

В качестве объекта верификации использовалась полносвязная сеть 
с одним скрытым слоем:
$$f(\mathbf{x}) = W_2 \cdot \mathrm{ReLU}(W_1 \mathbf{x} + \mathbf{b}_1) + \mathbf{b}_2,$$
где $W_1 \in \mathbb{R}^{H \times D}$, $W_2 \in \mathbb{R}^{1 \times H}$, 
$D = 4096$~--- размерность входа, $H = 262144$~--- размерность 
скрытого слоя. Матрица $W_1$ размера $262144 \times 4096$ 
(около 4~ГБ в float32) доминирует в потреблении памяти 
как при прямом проходе, так и при вычислении backward bounds 
в CROWN.

\subsubsection{Реализация Tensor Parallelism}

Для TP-варианта модель была разбита по схеме 
Megatron-LM\cite{MegatronLM2020}:
\begin{itemize}
    \item \textbf{Column Parallel} ($W_1$): весовая матрица 
    разрезана по столбцам (по выходному измерению). Каждый GPU 
    хранит шард $W_1^{(r)} \in \mathbb{R}^{(H/P) \times D}$, 
    где $P$~--- число GPU.
    \item \textbf{Row Parallel} ($W_2$): весовая матрица 
    разрезана по строкам (по входному измерению). Каждый GPU 
    хранит шард $W_2^{(r)} \in \mathbb{R}^{1 \times (H/P)}$, 
    вычисляет частичный результат, после чего выполняется 
    \texttt{AllReduce} (суммирование) для получения полного выхода.
\end{itemize}

Для интеграции с \texttt{auto\_LiRPA}\cite{AutoLiRPARepo} были 
реализованы операторы bound propagation 
(\texttt{BoundLinearTP\_Col}, \texttt{BoundLinearTP\_Row}), 
наследующие от \texttt{BoundLinear} и добавляющие 
\texttt{AllReduce} на этапе обратного распространения границ.

\subsubsection{Методология}

Верификация выполнялась методом CROWN для свойства локальной 
робастности в $L_\infty$-норме с $\varepsilon = 0.01$ на батче 
из $N = 2048$ входных примеров размерности $D = 4096$, 
сгенерированных случайно. Измерялось пиковое потребление 
GPU-памяти (\texttt{torch.cuda.max\_memory\_allocated}).

\subsection{Эксперимент 2: корректность и звуковость bounds}

\subsubsection{Методология}

Для проверки корректности TP-реализации использовались модели 
MLP разной глубины. Для каждой модели вычислялись bounds двумя 
способами:
\begin{enumerate}
    \item \textbf{Эталон:} стандартный CROWN на одном GPU 
    (полная весовая матрица, без \texttt{AllReduce}).
    \item \textbf{TP=2:} CROWN с Tensor Parallelism на двух GPU 
    (шардированные весовые матрицы с \texttt{AllReduce}).
\end{enumerate}

Проверялись три свойства:
\begin{itemize}
    \item \textbf{Точность:} максимальное отклонение 
    $|lb_{\text{ref}} - lb_{\text{tp}}|$ и 
    $|ub_{\text{ref}} - ub_{\text{tp}}|$.
    \item \textbf{Звуковость:} 
    $lb_{\text{tp}} \leq lb_{\text{ref}}$ и 
    $ub_{\text{tp}} \geq ub_{\text{ref}}$ для всех выходов 
    (TP-bounds должны быть шире эталона).
    \item \textbf{Кросс-ранговая согласованность:} оба GPU 
    должны получить идентичные bounds.
\end{itemize}

Модели PyTorch генерировались программно; модели ONNX были 
загружены из бенчмарка VNN-COMP 2022 
(MNIST-FC)\cite{arXiv2212VNNCOMP2022}. 
Верификация проводилась с $\varepsilon = 0.02$ для 
$L_\infty$-робастности.

\subsubsection{Анализ результатов}

Результаты демонстрируют два ключевых свойства реализации:

\textbf{1. Точность для одной пары Col-Row.} Модели с одной 
парой Column--Row (256$\times$2) дают bounds, совпадающие 
с эталоном с точностью до машинного эпсилона ($\sim 10^{-8}$). 
Это подтверждает арифметическую корректность реализации: 
\texttt{AllReduce} в CROWN backward точно воспроизводит 
результат полного матричного умножения.

\textbf{2. Звуковость с потерей точности для нескольких пар.} 
Модели с несколькими парами (256$\times$4, 256$\times$6) 
дают bounds, которые \textit{шире} эталона (звуковая 
овер-аппроксимация), но менее точны. Потеря точности 
растёт с числом шардированных зон. Это фундаментальное 
следствие архитектуры TP для верификации: промежуточные 
bounds для узлов в шардированных зонах вычисляются методом 
IBP (а не CROWN), поскольку CROWN backward не может 
корректно пересекать границы зон с частичными весовыми 
матрицами. IBP даёт более рыхлые, но гарантированно 
звуковые промежуточные bounds, что приводит к 
овер-аппроксимации в последующих слоях.

\textbf{3. Идеальная кросс-ранговая согласованность.} 
Все модели показывают нулевое расхождение между GPU, 
подтверждая детерминированность вычислений и корректность 
\texttt{AllReduce}-синхронизации.

\subsection{Эксперимент 3: автоматическое шардирование моделей VNN-COMP}

Третий эксперимент проверял работоспособность функции 
автоматического шардирования \texttt{tp\_shard\_bounded\_module} 
на моделях из бенчмарка VNN-COMP 2022\cite{arXiv2212VNNCOMP2022}. 
Модели MNIST-FC (полносвязные сети для классификации MNIST) были 
загружены в формате ONNX, преобразованы в PyTorch с помощью 
\texttt{onnx2pytorch}, обёрнуты в \texttt{BoundedModule} 
и автоматически шардированы без ручного вмешательства.

Функция \texttt{tp\_shard\_bounded\_module} выполняет 
следующие шаги:
\begin{enumerate}
    \item Обход вычислительного графа \texttt{BoundedModule} 
    в топологическом порядке.
    \item Идентификация чередующихся пар \texttt{BoundLinear}.
    \item Замена на \texttt{BoundLinearTP\_Col} / 
    \texttt{BoundLinearTP\_Row} с шардированием весов.
    \item Обновление метаданных графа (размерности выходов, 
    forward-значения) через повторный прямой проход.
    \item Разметка шардированных зон для корректного 
    вычисления промежуточных bounds.
\end{enumerate}

Все три протестированные модели VNN-COMP (256$\times$2, 
256$\times$4, 256$\times$6) были успешно шардированы и прошли 
тест на звуковость (см. Таблицу~\ref{tab:tp-correctness}), 
подтверждая применимость подхода к произвольным 
полносвязным моделям.

(single-GPU и FSDP$=$2) с проверкой точности, кросс-ранговой 
согласованности и звуковости. Тестировались модели MLP 
(программно сгенерированные, $h = 256$, глубина 2, 4, 6 слоёв)

\subsubsection{Анализ результатов}

FSDP даёт \textit{побитово идентичные} bounds для всех 
протестированных моделей и методов. Отклонение от 
single-GPU составляет $0.00$~--- точный ноль, а не 
машинный эпсилон. Это фундаментальное отличие от TP 
(см.~Таблицу~\ref{tab:tp-correctness}), где модели 
с несколькими шардированными зонами (256$\times$4, 256$\times$6) 
демонстрировали потерю точности на порядки из-за IBP 
fallback для промежуточных bounds.

\textit{полную} весовую матрицу (собранную \texttt{AllGather} 
из шардов) перед вычислением bounds, поэтому все операции 
(IBP, CROWN backward) арифметически идентичны 
однопроцессорному режиму. Шардирование влияет только 
на хранение весов, но не на вычисления.

\subsection{Эксперимент 5: потребление GPU-памяти при FSDP}

\subsubsection{Методология}

Измерялись два показателя потребления GPU-памяти:

\begin{enumerate}
    \item \textbf{Baseline-память}~--- объём памяти, занятый 
    после инициализации \texttt{BoundedModule} и шардирования 
    (для FSDP), но до вызова \texttt{compute\_bounds}. 
    Отражает стоимость хранения весов модели.
    
    \item \textbf{Peak-память}~--- пиковое потребление 
    (\texttt{max\_memory\_allocated}) во время 
    \texttt{compute\_bounds}. Включает веса, A-матрицы CROWN, 
    промежуточные тензоры и буферы NCCL.
\end{enumerate}

Тестировались MLP-модели с различной шириной скрытого слоя 
($h \in \{256, 1024, 4096, 8192\}$, глубина~4) и глубиной 
($d \in \{2, 4, 6, 8\}$, ширина~4096). Верификация методом 
CROWN, $\varepsilon = 0.02$, входная размерность $784$ 
(MNIST). Для FSDP запускалось два GPU ($P = 2$), память 
бралась как максимум по обоим рангам.

\subsubsection{Анализ результатов}

\textbf{1. Baseline-память.} FSDP сокращает память хранения 
весов на 57--90\%, причём экономия растёт с размером модели: 
для малых моделей ($h = 256$) фиксированные накладные расходы 
(метаданные графа, буферы NCCL) составляют заметную долю, 
тогда как для моделей с $h \geq 4096$ экономия 
стабилизируется на $\sim\!82\%$, приближаясь к теоретическому 
пределу $1/P + 1/d$ (см. раздел~\ref{sec:fsdp-memory-theory}).

\textbf{2. Пиковая память.} Экономия пиковой памяти 
составляет 34--39\%~--- существенно ниже baseline-экономии. 
Это объясняется тем, что FSDP шардирует \textit{только 
веса}, тогда как A-матрицы CROWN (матрицы коэффициентов 
линейной релаксации, обратно распространяемые по графу) 
имеют полную размерность $O(h \times h)$ на каждом GPU. 
При $d = 4$ слоях A-матрицы сопоставимы по объёму с весами, 
поэтому шардирование одних весов даёт $\sim\!34\%$. 
При $d = 8$ доля весов в пиковой памяти выше, 
и экономия увеличивается до 39\%.

\textbf{3. Сравнение с TP.} TP (Эксперимент~1)
достигает $\sim\!2\times$ снижения пиковой памяти,
поскольку шардирует \textit{и веса, и A-матрицы}
(A-матрицы проходят через слои с уменьшенной
размерностью $h/P$). Однако TP теряет точность bounds
для глубоких моделей. FSDP представляет собой
компромиссный подход: умеренная экономия памяти
при \textit{идеальной} точности bounds, что критично
для полной верификации ($\beta$-CROWN).

\subsection{Эксперимент 6: FSDP в полной верификации (BaB)}
\label{sec:exp6}

\subsubsection{Мотивация и корректировка методологии}

Полная верификация ($\beta$-CROWN~\cite{betaCROWN2021} +
Branch-and-Bound, BaB) существенно отличается от неполной:
она итеративно разбивает входное пространство на поддомены,
оптимизирует $\alpha$- и $\beta$-параметры для каждого
поддомена и хранит дерево поддоменов в памяти GPU.
Основными потребителями памяти здесь становятся
alpha-тензоры~--- per-neuron наклоны ReLU-аппроксимации
$\alpha_{i,k} \in [0, 1]$, размерность которых равна
$(\text{число слоёв}) \times (\text{число спецификаций}) \times
(\text{batch}) \times (\text{нейронов в слое})$.

При разработке честного сравнения обнаружилось, что
предварительные результаты содержали системный артефакт:
режим single-GPU использовал \texttt{auto\_enlarge\_batch\_size}
(автоматически увеличивал batch, заполняя GPU) и
\texttt{pruning\_in\_iteration} (раннее завершение раунда),
тогда как FSDP-режим эти оптимизации отключал для
синхронизации AllGather. В итоге сравнивались
\textit{разные нагрузки}, из-за чего получалось ложное
«27-кратное» преимущество FSDP.

Для устранения артефакта реализована опция
\texttt{bab.force\_synchronous} (CLI: \texttt{--force\_synchronous}),
которая принудительно включает тот же код-путь BaB,
что и при активном FSDP: фиксированный batch, без
\texttt{auto\_enlarge\_batch\_size}, без
\texttt{early\_stop}, без \texttt{pruning\_in\_iteration}.
Это обеспечивает \textit{идентичный workload} обоих режимов.

\subsection{Эксперимент 7: FSDP с ViT из VNN-COMP'23}
\label{sec:exp7}

\subsubsection{Модель и JIT-совместимость}

Модель \texttt{pgd\_2\_3\_16} ($2$ трансформер-блока,
$3$ heads, $\sim\!75$K параметров, $\sim\!0.3$~МБ весов)
из VNN-COMP 2023. В отличие от MLP, трансформер
использует динамические reshape-операции, несовместимые
с JIT-трассировкой, которую применяет auto\_LiRPA
для построения вычислительного графа.

Для поддержки ViT потребовалось устранить три класса
JIT-несовместимостей в \texttt{auto\_LiRPA}:
\begin{enumerate}
    \item \textbf{\texttt{BoundReshape}}: при JIT-трассировке
    размерность батча «запекается» в граф как константа.
    Исправление: при условии, что общее число элементов
    совпадает, первая ось shape заменяется на текущий
    batch-size. Проверка $\prod(\text{new\_shape}) = x.\text{numel}()$
    предотвращает некорректную замену при reshape вида
    $[B, N, D] \to [B \cdot N, D]$.
    \item \textbf{\texttt{BoundConcat}}: JIT фиксировал
    число конкатенируемых тензоров как константу.
    \item \textbf{\texttt{BoundConstantOfShape}}: замена
    JIT-запечённой формы на текущую.
\end{enumerate}

\subsection{Эксперимент 8: расширение FSDP на свёрточные слои}
\label{sec:exp8}

\subsubsection{Реализация}

Предыдущие эксперименты охватывали только полносвязные
слои (\texttt{BoundLinear}). Для применения к реальным
сетям компьютерного зрения (ResNet, VGG) FSDP расширен
на свёрточные слои (\texttt{BoundConv}).

Весовые тензоры свёртки имеют форму
$[C_\text{out}, C_\text{in}, k_H, k_W]$; шардирование
выполняется по измерению $0$ (выходные каналы $C_\text{out}$)
--- аналогично шардированию по строкам у \texttt{BoundLinear}.
Это единственное измерение, по которому слой является
«линейным по выходу» и по которому AllGather корректно
восстанавливает полную матрицу.

Изменения коснулись трёх компонентов:
\begin{enumerate}
    \item \texttt{fsdp\_utils.py}~--- \texttt{shardable\_types
    = (BoundLinear, BoundConv)}, защита от двойного
    шардирования, исправление \texttt{fsdp\_free\_node}
    (замена \texttt{= None} на \texttt{delattr} для
    корректной семантики \texttt{hasattr}).
    \item \texttt{backward\_bound.py}~--- AllGather/free
    для \texttt{BoundConv} в CROWN backward pass.
    \item \texttt{interval\_bound.py}~--- free-хуки
    для \texttt{BoundConv} после IBP propagate.
\end{enumerate}

\subsubsection{Методология}

Использовались модели ResNet из VNN-COMP 2024
(CIFAR-100): \texttt{CIFAR100\_resnet\_medium} и
\texttt{CIFAR100\_resnet\_large}. Fair-условия:
\texttt{force\_synchronous}, batch$=$64, max\_iterations$=$5.

\subsubsection{Анализ результатов}

\textbf{Корректность и полный результат верификации.}
Bounds побитово идентичны для обеих моделей.
Для ResNet-large получен \textit{полный} результат
верификации (unsat): $\alpha$-CROWN на стадии инициализации
доказал свойство (min-margin $\ge 0$ для всех выходных
классов), BaB не потребовался. Это первый в данной работе
случай, когда верификатор с FSDP завершил задачу с
гарантированным ответом, а не превысил бюджет.
Оба режима (single-GPU и FSDP$=$2) вернули идентичный
результат, что подтверждает корректность реализации
BoundConv-шардирования в полной цепочке верификации.

\textbf{Память.} ResNet-large содержит $\sim\!95$~МБ
свёрточных весов, однако $\alpha$-тензоры занимают
более $4$~ГБ. Причина: $\alpha$-тензоры не шардируются;
каждый GPU хранит полный набор per-neuron slopes
для всего batch. При $\alpha$-CROWN overhead AllGather
($\sim\!30$~МБ) превышает экономию от шардирования
$95$~МБ весов на $P=2$.

\textbf{Узкое место.} В режиме $\alpha$-CROWN+BaB
узкое место по памяти~--- не веса, а $\alpha$-тензоры.
Для получения заметной экономии необходимо шардировать
$\alpha$-тензоры, что является следующим шагом разработки.
