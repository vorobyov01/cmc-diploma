\section{Анализ алгоритмов и верификаторов}

\subsection{Иерархия методов распространения границ}

Основу современных верификаторов составляют алгоритмы bound
propagation~--- они вычисляют для каждого выхода сети интервал,
гарантированно содержащий истинное значение при любом допустимом входе.
По точности и вычислительной стоимости таких алгоритмов выделяют
три уровня.

\textbf{IBP (Interval Bound Propagation)} распространяет интервалы
$[\mathbf{l}, \mathbf{u}]$ послойно через сеть.
Для линейного слоя $\mathbf{y} = W\mathbf{x} + \mathbf{b}$:
$$\mathbf{l}_y = W^+\mathbf{l}_x + W^-\mathbf{u}_x + \mathbf{b}, \quad
  \mathbf{u}_y = W^+\mathbf{u}_x + W^-\mathbf{l}_x + \mathbf{b},$$
где $W^+ = \max(W, 0)$, $W^- = \min(W, 0)$ поэлементно.
Метод дешевый ($O(n)$, один проход), но с ростом глубины интервалы
быстро расширяются из-за накопления ошибки овер-аппроксимации.\cite{CROWNPaper}

\textbf{CROWN (Convex Relaxation with Optimized Neurons)} считает
bounds обратным проходом, как backpropagation при обучении.
Для ReLU-нейрона при $x \in [l, u]$, $l < 0 < u$, строится линейная
релаксация:
$$\lambda_l x + b_l \leq \mathrm{ReLU}(x) \leq \frac{u}{u - l}(x - l),$$
где $\lambda_l \in [0, 1]$ фиксируется эвристически.
Обратный проход связывает выход сети с входом через цепочку линейных
неравенств~--- bounds получаются существенно точнее, чем у IBP.\cite{CROWNPaper}

\textbf{$\alpha$-CROWN} идёт дальше: наклоны $\lambda_l$ становятся
оптимизируемыми параметрами $\alpha_i$ для каждого нейрона.
Градиентный спуск по $\alpha$ поднимает нижнюю границу (или опускает
верхнюю), выдавая наиболее точные bounds без какого-либо
ветвления.\cite{AlphaBetaCrownVNNCOMP23}

\subsubsection{Неполная и полная верификация}

IBP, CROWN и $\alpha$-CROWN~--- методы \textit{неполной верификации}
(incomplete verification). Они строят овер-аппроксимацию множества
выходов, удовлетворяющую \textit{soundness}: нижние bounds не
превышают истинных минимумов, верхние~--- не ниже истинных максимумов.
Когда полученные bounds достаточно узки, чтобы подтвердить свойство,
верификация успешна; иначе~--- результат неопределённый.
Важно, что ложного подтверждения такой метод не даёт никогда:
если свойство нарушается хоть для одного входа, bounds это отразят.

\textit{Полная верификация} (complete verification) гарантирует ответ:
либо <<свойство выполняется>>, либо предъявляется контрпример.
Для этого применяется \textit{Branch-and-Bound} (BaB): если bounds
недостаточно точны, пространство входов разбивается на подобласти
(например, фиксацией состояния ReLU: $x \geq 0$ или $x < 0$),
и bounds пересчитываются для каждой.
Процесс повторяется до получения ответа или исчерпания ресурсов.

\subsubsection{Алгоритм Branch-and-Bound и стратегии ветвления}
\label{sec:bab-algorithm}

Branch-and-Bound поддерживает приоритетную очередь нерешённых
\textit{поддоменов}~--- подзадач, каждая из которых задана
ограничениями на состояния ReLU-нейронов или на входное пространство.
Изначально очередь содержит единственный поддомен~--- полную
область $\mathcal{X}$.

На каждой итерации из очереди извлекается поддомен с минимальной
нижней границей (best-first search) и для него запускается
$\alpha$-CROWN.
Если нижняя граница~$\ge 0$~--- поддомен закрыт (свойство доказано);
если верхняя~$< 0$~--- найден контрпример.
Иначе поддомен разбивается на два дочерних и возвращается в очередь.

Производительность BaB определяется двумя вещами: скоростью
bound propagation и \textbf{стратегией ветвления}~--- выбором
нейрона или оси для разбиения поддомена.

\paragraph{Разбиение по активациям (activation split).}
Фиксируется состояние одного <<неопределённого>> ReLU-нейрона
($l < 0 < u$): в первом дочернем поддомене добавляется ограничение
$x_i \ge 0$, во втором~--- $x_i < 0$.
В каждом из них нейрон уже не требует линейной релаксации~---
bounds на последующих слоях становятся точнее.

\paragraph{Разбиение по входу (input split).}
Область $\mathcal{X}$ делится на два подкуба вдоль одной координаты
входного вектора.
Метод хорошо работает при малой входной размерности~--- например,
в задаче ACAS~Xu с входом $\mathbb{R}^5$~--- и применяется
в верификаторе VeriNet.

\paragraph{Эвристики выбора нейрона.}
Перебор всех кандидатов дорог; на практике используют три подхода.

\textbf{BaBSR}\cite{AlphaBetaCrownVNNCOMP23}~--- приближённая оценка
прироста нижней границы при фиксации каждого кандидата, вычисленная
через чувствительность $\alpha$-CROWN к значениям нейрона; выбирается
нейрон с максимальной оценкой.

\textbf{FSB} (Full Strong Branching)~--- полный пересчёт bounds
для каждого кандидата: даёт оптимальный выбор, но требует в $k$
раз больше вычислений, где $k$~--- число кандидатов.

\textbf{GNN-based branching}\cite{AlphaBetaCrownVNNCOMP23}~---
нейронная сеть на основе GNN обрабатывает граф модели и предсказывает
<<важность>> каждого нейрона для ветвления; оценка производится
за один прямой проход и по качеству сопоставима с~FSB.

Batch BaB в \texttt{auto\_LiRPA} собирает до $10^5$ поддоменов
в один батч и вычисляет bounds для всех за одно матричное умножение
на GPU~--- именно это делает GPU-верификаторы на порядки быстрее
CPU-реализаций.
Именно это делает возможным \textit{Domain Parallelism}~---
распределение батча поддоменов по нескольким GPU~---
рассматриваемый в разделе~\ref{sec:domain-parallel}.

\subsection{Alpha-Beta-CROWN}

$\alpha,\beta$-CROWN\cite{AlphaBetaCrownVNNCOMP23}~--- победитель
VNN-COMP с 2021 по 2024 год~--- объединяет описанные методы в единый
верификатор. Для неполной верификации он использует $\alpha$-CROWN;
если та не даёт достаточно точных bounds, переходит к полной верификации
через BaB.

\textbf{$\beta$-CROWN: полная верификация без LP.}
Традиционные BaB-верификаторы (например, MIPVerify) в каждом листе
дерева поиска решают задачу линейного программирования~--- это медленно
и требует переноса данных с GPU на CPU.
$\beta$-CROWN кодирует ограничения ветвления
(<<нейрон $i > 0$>> или <<нейрон $i \leq 0$>>)
непосредственно в процедуру bound propagation через двойственные
переменные Лагранжа ($\beta$).
В результате оценка bounds для тысяч ветвей выполняется параллельно
на GPU как серия матричных умножений, а параметры $\beta$ оптимизируются
совместно с $\alpha$ через градиентный спуск.

\subsubsection{Метод секущих плоскостей}

Для усиления релаксаций без полного ветвления применяются секущие
плоскости (Cutting Planes) из целочисленного программирования.
GCP-CROWN добавляет линейные неравенства, связывающие значения нескольких
нейронов, и отсекает дробные решения, допустимые в LP-релаксации, но
недопустимые для реальной ReLU-сети.
BICCOS (Branch-and-bound Inferred Cuts with COnstraint Strengthening)
генерирует отсечения на основе логических импликаций в дереве поиска
и применяет их итеративно, усиливая bounds в корневых узлах~--- это
позволяет решать задачи, которые иначе потребовали бы слишком глубокого
ветвления.\cite{AutoLiRPAPracticeSlides}

\subsection{Другие верификаторы}

\textbf{VeriNet} использует Symbolic Interval Propagation (SIP):
вместо линейных неравенств CROWN сохраняет зависимости в виде
символьных выражений.
Инструмент особенно эффективен при расщеплении входного пространства
(Input Splitting)~--- стратегии, хорошо работающей при малой размерности
входа, как в задачах управления (ACAS~Xu).\cite{IntervalReachabilityAnalysis}

\textbf{nnenum} (победитель VNN-COMP 2020) динамически переключается
между уровнями точности представления множеств~--- от быстрых, но грубых
зонотопов до точных, но дорогих ImageStar-ов~--- в зависимости от
сложности текущей подзадачи.\cite{NNEnumPaper}

\textbf{Marabou~2.0} решает ту же проблему иначе: вместо бинарного
поиска по состояниям нейронов применяется процедура DeepSoI
(Sum of Infeasibilities)~--- непрерывная функция суммарного нарушения
ограничений ReLU, которую можно минимизировать градиентными методами.
Это превращает комбинаторный поиск в задачу оптимизации.\cite{arXiv2401Marabou2}

\textbf{NeuralSAT} адаптирует CDCL (Conflict-Driven Clause Learning)
из мира SAT-решателей: при обнаружении несовместимой комбинации
состояний нейронов она записывается как <<запрет>>, и при дальнейшем
поиске целые поддеревья отсекаются без повторного обхода.\cite{NeuralSATRepo}

\subsection{Библиотека \texorpdfstring{\texttt{auto\_LiRPA}}{auto\_LiRPA}}
\label{sec:auto_lirpa}

Все эксперименты настоящей работы проводились на основе
\texttt{auto\_LiRPA}\cite{AlphaBetaCrownVNNCOMP23}~---
библиотеки, на которой построен $\alpha,\beta$-CROWN.
Принцип её работы: операции bound propagation описываются как узлы
вычислительного графа PyTorch~--- тогда библиотека сама выводит граф
для верхних и нижних границ любого промежуточного узла сети.
Это позволяет верифицировать произвольные архитектуры
(CNN, ResNet, Transformer) без написания специализированного
кода.\cite{LiRPAVerifyRepo}

Критически важная особенность~--- \textit{batch BaB}: вместо
последовательной обработки ветвей верификатор собирает пакет из сотен
тысяч нерешённых подзадач и вычисляет bounds для всех них за один
GPU-проход.
Именно это делает реализацию параллелизма в \texttt{auto\_LiRPA}
нетривиальной задачей: любая модификация должна сохранять возможность
пакетной обработки и быть совместимой с вычислительным графом PyTorch.

\subsection{Соревнование VNN-COMP}
\label{sec:vnncomp}

Ежегодное соревнование VNN-COMP (Verification of Neural Networks
Competition)\cite{arXiv2212VNNCOMP2022} проводится с 2020~года
и служит объективным стандартом сравнения верификаторов.
Организаторы публикуют бенчмарки в форматах ONNX\,+\,VNN-LIB
за несколько дней до соревнования, чтобы участники не могли
оптимизировать инструменты под конкретные примеры.
Каждый инструмент запускается с единым ограничением по времени
(обычно 300~с на задачу) и оценивается по числу доказанных свойств.

С каждым годом целевые сети крупнеют на порядки.
Верификация CIFAR-100 ResNet-large ($\sim$95~МБ весов) при batch~BaB
требует десятков гигабайт GPU-памяти на A-матрицы и per-neuron
$\alpha$-тензоры~--- на одном ускорителе это недостижимо.
Именно этот разрыв и мотивирует многоGPU-подходы данной работы.
